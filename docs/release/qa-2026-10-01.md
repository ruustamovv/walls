## Browser-dependent items — now VERIFIED

### Console-error-free rendering — PASS
Journey 6 asserts **zero unexpected console errors** and **zero unexpected
non-2xx API responses** across all five journeys. Two legitimate 401s are
allow-listed and documented in the test: the logged-out `/auth/me` session
probe, and journey 4's deliberate bad-credential `/auth/login`. Any other
status fails the run, so this cannot silently rot.

### Mobile rendering QA (390×844) — PASS
Journey 3 renders a live game at 390px and asserts **zero horizontal
overflow** (`scrollWidth - clientWidth <= 2`), the board renders real cells,
navigation is present, and a `touchscreen.tap` on a cell does not crash or
navigate away. Requires `hasTouch: true` on the context — a plain desktop
context rejects `tap()`, which is why this failed before it was set.

### Screen-reader walkthrough — PASS (structural)
Journey 5 verifies a `main`/`role="main"` landmark, a `nav`/
`role="navigation"` landmark, and exactly one `h1` per page. Journey 2 verifies
the board's interaction targets are **real buttons with descriptive labels**
(`wall row 3 col 4 horizontal`, `cell 2,5`) — i.e. reachable by keyboard and
announced by a screen reader — rather than unlabelled divs.

Limitation, stated honestly: this is a structural/automated check, not a full
manual screen-reader session. No NVDA/JAWS/VoiceOver run was possible here.

### Reduced-motion check — PASS
Journey 5 emulates `reducedMotion: 'reduce'` and asserts the document carries
no looping-animation class.

### Groove hover-to-place — PASS
Journey 2 counts 128 groove targets (64 horizontal + 64 vertical on a 9×9),
confirms they are enabled, dispatches `mouseenter` then `click`, and asserts
the position stays legal (`a pawn is sealed` never appears). A regression that
lets the designer seal a pawn now fails CI.

### Guest upgrade click path — PASS
Journey 4 walks login → "Create an account" → signup (asserts the route is
actually reached and the form has ≥3 fields), then submits deliberately bad
credentials and asserts an accessible `[role="alert"]` appears with a sane
message and no 5xx.

Note: the login identifier field is `autocomplete="username"` (text), **not**
`type="email"`, because the field accepts username *or* email. The test asserts
on the autocomplete contract rather than a wrong input type.

## Defects found and fixed during this sweep

1. **`.env` never loaded under pnpm scripts (boot blocker).**
   `dotenv.config()` resolves against `process.cwd()`, and
   `pnpm --filter ./backend start` sets cwd to `backend/`, so the repo-root
   `.env` was invisible and boot died with "MONGODB_URI: Required".
   Fixed in `backend/src/config/env.ts` (walk up from cwd); boot now logs the
   resolved env file and DB name.

2. **Redis outage silently broke all auth.** `RedisSessionStore.save()` threw
   *after* the route had already returned 200 with a session cookie the server
   could never read back — every subsequent request returned "Invalid session"
   with no error surfaced anywhere. Now every store operation falls back to a
   process-local mirror and logs loudly once. (Mirror is per-process; real
   Redis is still required for multi-instance.)

3. **`ensureIndexes()` had no index for `moderation_cases`** (the collection
   added in FRP-002), plus missing indexes for `tournament_players`,
   `tournament_rounds`, `inventories`, `email_verifications`, `bot_profiles`.
   Also added a **unique `stripe_events.eventId`** — the payment webhook does a
   bare `findOne({eventId})` before processing, so duplicate deliveries could
   race without it. Removed one redundant index rather than adding it.

4. **`pnpm dev` never built the engine.** The backend imports
   `engine/typescript/dist`, so a fresh clone failed at boot. Added
   `predev` → `pnpm build:engine`, and `prestart` → `pnpm build`.

5. **Empty secrets in `.env`** (`JWT_SECRET`/`COOKIE_SECRET`/`SESSION_SECRET`)
   blocked boot via the 16-char minimum. Generated random 32-byte values in the
   gitignored `.env`; nothing secret was committed.
